# ai-prompts

Источник промптов, паттернов и контрактов для проектов-потребителей.
Человеку — `README.md`. Локальный контракт — самостоятельный v2:
основная сессия сама ведёт код и документацию, без обязательных ролей,
брифинга, worktree, harness или запечатанной памяти. Продукты v3 в
`prompts/`, `skills/`, `agents/`, `packages/` и `design/` сохраняются.

## До поиска и чтения кода

Прочитай `context/project.yml`, `context/index.yml`, `context/workflow.md`,
`context/conventions/project-knowledge.yml`, затем выбранные по индексу
conventions и доменные документы namespace задачи.
Только после этого ищи и читай код, планируй или правь. Быстрый вопрос,
read-only разведка и знакомый проект этот порядок не отменяют.
Нет карты или нужного документа — сначала проверь известные пути документации;
обозначь пробел и только затем точечно исследуй код для его восполнения.

## Открытая проектная документация

Все существенные проектные правила, знания, факты и решения закрепляй явно
в канонических файлах, находимых через `context/index.yml`. До добавления
определения и перед «Готово» применяй единство источника правды из
`context/conventions/project-knowledge.yml`. В согласованном тикете
необходимая документация — часть готовности, отдельное «запомни» не нужно.
Memory агента, `MEMORY.md`, memory-сервисы, глобальные инструкции и личные
неиндексируемые заметки — не альтернативное и не параллельное хранилище.
Техническая возможность записи не даёт разрешения.

## Где искать ответ и границы

- Договорённости — `context/conventions/`; очередь — `context/views/goals.yaml`
  и skill `goals`; текущее устройство — доменные документы и указанный ими код.
- Почему/когда — `CHANGELOG.md`, затем git log; как добавить source —
  `CONTRIBUTING.md`, паттерны — `patterns/README.md`.
- Перед кодом читай `typescript`, перед внешним действием — `external-actions`,
  перед итоговыми проверками — `repository-checks`; execution evidence —
  `execution-artifacts` (ключи conventions из индекса).
- Ничего не создавать, переносить, удалять или пересматривать без явного «да»
  на объём. Обычные уточнения документации внутри согласованной работы делай сам.
- Git/arc write выполняет пользователь; ограничения автономии и глобальные
  guards не ослабляются сменой контракта.
- Содержание — на русском, commit message — на английском (`language`).

## Skills по задаче

Канон этого source repo — `skills/`, discovery — `./skills`; копий
`.agents/skills` и `.agents/agents` не создаём. Не читай все skills при старте.
Если skill-инструмента нет, прочитай соответствующий `skills/<name>/SKILL.md`:

- авторская правка skills → `skill-builder`;
- manuals или человеческая процедура → `manuals`;
- планирование, очередь, статус, «что дальше» → `goals`;
- установка/миграция документации → `contract-setup`, reference v2;
- сверка источников и модулей → `source-sync`, reference v2.

## Инструменты и исход работы

При трёх и более шагах, нескольких результатах или сложной задаче используй
todo; выбор из вариантов — доступной формой `question`. Независимые ветви
сложной работы — параллельным помощникам, если доступны и не запрещены.
«Без ролей» не запрещает субагентов. Fallback и полный протокол —
`context/workflow.md`.

Явно обозначай «Готово», «Продолжаю», «Нужен ответ» или «Нужно действие»
по ближайшему необходимому ходу. После «Продолжаю» сам выполняй следующий шаг.
Новое сообщение учитывай по ходу, не отменяя задачу без явного «стоп/вместо».
Для действия человека назови что, зачем, ожидаемый результат и возобновление.
Условия фонового продолжения, сценарии и чеклист тикета — `context/workflow.md`.
