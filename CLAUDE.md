# CLAUDE.md

Это репозиторий `ai-prompts` — личная коллекция промптов для работы с
AI-агентами. Ты (агент) читаешь этот файл первым, чтобы понять маршрут.

## Порядок чтения

1. Этот файл.
2. `README.md` — что за проект и как им пользуются.
3. `CONTRIBUTING.md` — правила добавления промпта.
4. `patterns/README.md` — модель переиспользуемых паттернов и как их
   применять.
5. `prompts/modules/README.md` — модель модулей расширения (надстройки
   над базовыми промптами).
6. `prompts/index.yml` — сгенерированный индекс всех промптов (ключи,
   пути, SHA-256, `applicable_to`). Читай для навигации и справки, но
   правда — в самих файлах.
7. Конкретные шаблоны в `patterns/<key>.md` — по мере необходимости.
8. Конкретные промпты в `prompts/<category>/<name>.md` и модули в
   `prompts/modules/<key>.md` — по задаче.
9. Skills в `skills/<name>/`, субагенты в `agents/<name>.md` и пресеты
   в `presets/<key>.yml` — то, что контракты и модули ставят в проекты;
   по задаче.

## Работа с промптами

Промпт — самодостаточный `.md`-файл, который скармливается агенту одной
ссылкой или копипастой. Формат и требования — в `CONTRIBUTING.md`.

Каждый промпт в frontmatter обязательно объявляет `kind`
(`contract` / `pattern` / `module` / `prompt`) и может декларировать
применённые паттерны:

```yaml
kind: contract
patterns: [source-sync, ...]
```

Паттерн — переиспользуемый блок правил, живущий в `patterns/<key>.md`.
Его содержимое инлайнится в тело промпта как раздел (гибрид «декларация
+ inline-копия»): промпт остаётся самодостаточным, но при этом ясно, что
это применение общего паттерна. Inline-копия может жить и в skill,
который промпт ставит в проект (так в v3: `goals` → skill `goals`).

Модуль — надстройка над конкретной базой, живёт в
`prompts/modules/<key>.md`. В отличие от паттерна не инлайнится в базу,
а подключается проектом-потребителем как отдельная сущность. Подробнее —
`prompts/modules/README.md`.

## Индекс промптов

`prompts/index.yml` — единый сгенерированный каталог всех промптов
репозитория (ключи, пути, raw-URL, SHA-256, `applicable_to`).
Используется проектами-потребителями для быстрой синхронизации через
`source-sync` (см. `patterns/source-sync.md`): проект тянет один
`index.yml`, сравнивает SHA всех подключённых источников и анализирует
только разошедшиеся.

**После правки любого промпта, паттерна или модуля — обязательно
запусти `npm run index:build`** и включи обновлённый `index.yml` в
тот же коммит. CI проверяет консистентность через `npm run index:check`
и валит билд при рассинхроне.

Индекс собирает harness (`harness/packages/harness`, TS). Нужен
Node ≥ 24; перед первым запуском — `npm ci && npm run build`.

## При добавлении или правке промпта

Перед планом:

1. Прочитай `patterns/README.md` и список файлов в `patterns/`.
2. В плане перечисли применимые паттерны с одностроковым trade-off
   каждый.
3. Одной строкой — свою рекомендацию: какие применяем.
4. Жди моего выбора. Не применяй паттерны молча.

При обновлении промпта, у которого в frontmatter уже задекларированы
паттерны — сверь его inline-секции с текущим содержимым соответствующих
`patterns/<key>.md`. Если паттерн обновился, а inline-копия отстала —
подними это в отчёте и предложи план миграции.

## Worktrees

Параллельная работа над разными промптами ведётся в отдельных git
worktree — одна задача, одна ветка, один worktree.

- Worktrees живут в `.claude/worktrees/<name>` (создаются через
  `claude --worktree <name>` или `EnterWorktree`). Каталог уже
  игнорируется через `.claude/` в `.gitignore`.
- `.worktreeinclude` в корне перечисляет игнорируемые файлы, которые
  копируются в каждый новый worktree (локальные настройки агента).
- В новом worktree сначала `npm ci && npm run build`: `node_modules/`
  и `dist/` у каждого worktree свои, через `.worktreeinclude` их не
  копируем.
- `npm run index:build` запускай внутри своего worktree: у каждой
  ветки свой `prompts/index.yml`. При конфликте в `index.yml` после
  merge — не правь руками, а пересобери той же командой.
- После merge ветки worktree удаляется (`git worktree remove`).

## Фазы и коммиты

Атомарность фазы — это **связность**, а не однотипность: фаза — одна
законченная по смыслу задача целиком. Код, сгенерированные артефакты
(`index.yml`), тесты и связанная правка документации идут вместе, одной
фазой и одним коммитом. Тип коммита (karma commit-msg) — по главному
смыслу фазы. Отдельная фаза нужна только для другой задачи: «заодно
поправлю несвязанное» — нельзя, «доведу эту же задачу до конца» — нужно.

Остановка на согласование — на развилках, требующих решения
пользователя, и в конце задачи, а не между её частями.

Типы применительно к этому репозиторию:

- `feat` — новый или изменённый промпт, паттерн, модуль;
- `fix` — исправление ошибки в существующем промпте / паттерне / модуле;
- `refactor` — перестройка без смены смысла (переименование, перекладка
  разделов);
- `docs` — `README.md`, `CONTRIBUTING.md`, `CLAUDE.md`, README в
  `patterns/` и `prompts/modules/`;
- `chore` — скрипты, CI, конфиги (`.gitignore`, `.worktreeinclude` и
  т.п.).

Формат сообщения: `type(scope): subject` на английском, scope — `key`
промпта / паттерна / модуля или затронутая область.

**Конец задачи:** короткий отчёт + предложенное сообщение коммита →
ждёшь «ок». К следующей задаче автоматически не переходишь.

**Git-решения принимает только человек.** Коммиты, пуши, ветки, PR,
merge, rebase, reset, stash и прочие write-операции делает пользователь.
Агент выполняет их только по явной просьбе и только после того, как
пользователь подтвердил список конкретных команд. Помимо названия
коммита в конце задачи — коммиты не предлагаешь и о них не напоминаешь.

## Язык

Вся содержательная часть — на русском. Английский допустим в
идентификаторах, ключах frontmatter, именах файлов и общеупотребимых
технических терминах.

## Что не делаем

- Не переносим правила проекта в глобальную memory агента или в hooks
  вне репозитория. Всё, что важно, живёт в этом репозитории (принцип
  открытости).
- Не создаём и не правим файлы без явного «да» на конкретный план.
- Не переименовываем существующие `key` промптов и паттернов без
  согласования: на них могут ссылаться извне.
