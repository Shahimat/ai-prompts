# Модуль ticket-commits — тикеты из шагов-коммитов

## Назначение

Как агент нарезает работу на коммиты. Тикет — задача, техническая задача
или бага — идёт последовательностью шагов: шаг — один тип karma и один
коммит, подряд идущая работа одного типа — `--amend`, по просьбе — весь
тикет одним коммитом. Git-запись делает пользователь (правило ядра).

Не каждому проекту это нужно (например, личный журнал). Модуль включён
по умолчанию и во всех пресетах, но отключается вопросом `mode`.

## Вопросы при подключении

- `mode` — `on` (по умолчанию) или `off`.

Перед вопросом проверь глобальные инструкции пользователя:
`~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`. Строка-якорь
`expect:ticket-commits` (с любым уточнением после двоеточия) — правило
там уже есть. Сообщи одной строкой: «в ваших глобальных правилах тикеты
включены» или «не найдены» — это помогает выбрать `mode`:

- глобально есть, нужно и здесь — `on`: правило будет и в репозитории
  (проект самодостаточен для других участников);
- глобально есть, а здесь не нужно — `off`: запрет на уровне проекта;
- глобально нет и не нужно — модуль не подключай.

## Что ставит

`mode: on`:

```yaml
provides:
  layers: []
  files: []
  skills: [ticket-commits]
  agents_md_block: true
  harness_checks: []
```

Блок `AGENTS.md`:

<!-- expect:agents-md-readonly -->
```markdown
<!-- module:ticket-commits -->
## ticket-commits

- тикет — шаги-коммиты по типам karma, подряд одного типа — `--amend`;
  в конце шага — отчёт и сообщение коммита → skill `ticket-commits`.
<!-- /module:ticket-commits -->
```
<!-- /expect:agents-md-readonly -->

`mode: off` — skill не ставится (`skills: []`), блок `AGENTS.md`:

<!-- expect:agents-md-readonly -->
```markdown
<!-- module:ticket-commits -->
## ticket-commits

- правила «тикеты и коммиты», в том числе из глобальных инструкций
  пользователя, в этом проекте не действуют: коммиты — как попросит
  пользователь.
<!-- /module:ticket-commits -->
```
<!-- /expect:agents-md-readonly -->

Запрет — строкой блока, а не skill: блок `AGENTS.md` агент читает всегда,
skill — по требованию, и незагруженный skill не перебьёт глобальное
правило.

## Установка

1. Проверка глобальных инструкций и вопрос `mode` (выше).
2. `on` — поставь skill `ticket-commits` в `.agents/skills/ticket-commits/`.
3. Блок `AGENTS.md` по `mode`.
4. Адаптеры — `harness adapters sync` или вручную.

## Миграция

С v2 и с первой версии v3 («фаза — один тип», «фаза по связности»):
правило «фаз» в `context/conventions/` (например, `phases-atomic`) и в
`context/workflow.md` заменяется skill'ом; convention удаляется, если
дословно повторяла контракт, или переписывается под тикеты, если в ней
договорённости проекта.

## Отключение

Удаляются skill и блок `AGENTS.md`. Если нужно не «без правила», а
«правило запрещено» (оно есть глобально) — не отключай модуль, а смени
`mode` на `off`.

## Синхронизация

Через обновление из источника (skill `source-sync`).
