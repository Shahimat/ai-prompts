# Модуль operator — оператор и политика автономии

## Назначение

Основная сессия становится оператором: держит намерение пользователя,
раздаёт работу ролям (модуль `roles`) и jobs (модуль `ops`), собирает
вопросы пачкой и возвращает короткую сводку. Состояние работ живёт в
файлах рантайма, а не в контексте: рестарт и чистка контекста ничего
не теряют.

Действия наружу — задачи, PR, сообщения людям, расписание машины —
опасны тем, что их делают от имени пользователя. Политика держится на
двух уровнях (паттерн `guardrail-dual-level`):

- **агент** — правило в блоке `AGENTS.md`: оператор и роли сверяются с
  политикой перед любым действием наружу;
- **рантайм** — `ops` не вызывает пишущие методы провайдеров без
  разрешения политики; `never` не обходится даже прямой командой.

## Что ставит

```yaml
provides:
  layers: []
  files: [context/autonomy.yml]
  skills: [operator]
  agents_md_block: true
  harness_checks: []
  changelog_tags: [autonomy]
```

`autonomy` — тег журнала для решения о политике: новое действие в
`self`, снятие запрета.

Стартовый `context/autonomy.yml` — всё наружу только после «да»,
git-запись — никогда:

```yaml
# Политика действий наружу. Формат — skill operator.
levels:
  self: []
  ask: []
  never: [vcs.write]
```

Блок `AGENTS.md` — правило целиком:

<!-- expect:agents-md-readonly -->
```markdown
<!-- module:operator -->
## operator

- основная сессия — оператор: раздаёт работу ролям и jobs, код и сырые ответы систем не читает → skill `operator`;
- действие наружу — только по `context/autonomy.yml`: self — сам, ask — после «да», never — никогда;
- git-запись — никогда сам; новое `self` — только решением пользователя;
- правило приоритетнее скорости; конфликт — стоп и вопрос.
<!-- /module:operator -->
```

## Установка

1. Проверь, что подключён `roles` (иначе `contract-setup` добавит).
2. Поставь skill `operator`, создай `context/autonomy.yml` по шаблону,
   добавь блок в `AGENTS.md`.
3. Спроси, какие действия пользователь готов отдать в `self` сразу
   (например, одобрение чужого PR после анализа). Каждое — явным «да»;
   решение — строкой журнала с тегом `autonomy` через docs-keeper.
4. Если подключён harness — тег `autonomy` в
   `context/ai-core.yml` → `checks.changelog.tags`.
5. Если подключён `domain` — предложи стартовую behavior уровня
   рантайма: «действие наружу вне политики не выполняется» с `check` —
   прогон с `never` для действия (план → «да» → через docs-keeper).

## Отключение

Отключение снимает приоритетное правило — вопрос пользователю с явным
подтверждением. Skill, блок и тег удаляются; `context/autonomy.yml` —
отдельный вопрос, записи журнала с тегом `autonomy` остаются. Модули
`ops`, `watchers`, `dashboard` требуют `operator` — сначала они.

## Синхронизация

Через обновление из источника (skill `source-sync`): модуль и skill
`operator` — по своим SHA. Inline-блок `guardrail-dual-level` в skill
обновляется вместе с паттерном.
