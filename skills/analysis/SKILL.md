# analysis

Слой обработки информации и собственных взглядов: внешнее и своё — в
одних сущностях, различаются провенансом. Метод — благожелательно-
критический: любая позиция сначала читается в сильнейшей форме.

## Маршруты

- что у нас есть про X → сценарий `inquiry` (ниже);
- откуда материал / что сказано и где → `analysis/sources/`,
  `analysis/claims/`;
- во что я верю → `analysis/positions/`, цельно — `analysis/posts/`;
- как я оцениваю объект → `analysis/analyses/`;
- где взгляды сталкиваются и как развились → `analysis/tensions/`;
- список id по namespace → `context/index.yml`; без него — поиск по
  `summary` в `analysis/`.

Читай сущности только нужного namespace.

## Целостность атрибуции

Выдуманная цитата или ложное приписывание отравляет всю систему и её
выводы. Правило — в блоке `AGENTS.md` модуля; здесь — полностью.

- **Ни одной выдуманной цитаты.** `quote` — только то, что реально есть
  в источнике и сверено. Не помнишь формулировку — пересказ с пометкой
  «пересказ».
- **Всё приписанное трассируется.** Утверждение, приписанное автору,
  политику **или мне**, несёт `locator`: книга — глава / страница /
  раздел; речь, статья — ссылка + дата, абзац или тайм-код; свой
  тезис — пост или позиция + дата.
- **Непроверенное помечается.** Нет доступа к оригиналу — `verified:
  false`, `verified_note: атрибуция не сверена: <почему>`; не
  додумывается.
- **Без подмены голоса.** Агент не протаскивает собственную
  политическую позицию; оценка помечается как оценка, факт — как факт
  с провенансом.
- **Три пласта не смешиваются.** Что человек сказал (`primary`), что о
  нём написали (`secondary`), что я думаю (`own`) — разные сущности,
  не одна строка.
- **Язык цитаты.** Дословно — на языке оригинала, перевод рядом с
  пометкой «перевод».
- **Сомнение** — в пользу «не сверено» и блокирующий вопрос (skill
  `workflow`). Тезис и оригинал расходятся — прав оригинал.

## Правило в двух уровнях

Применение паттерна `guardrail-dual-level` (см.
`patterns/guardrail-dual-level.md` в репозитории `ai-prompts`).
Inline-копия обновляется вместе с паттерном.

**Уровень агента.** Правило модуля — строками в его блоке `AGENTS.md`.
Обязательно наравне с жёсткими правилами ядра: дополняет их и не
отменяет. В пределах своей области (то, что описывает модуль) правило
приоритетнее формата сценария, удобства и скорости: при конфликте —
стоп и вопрос пользователю, а не тихий компромисс.

**Уровень приложения.** Если в проекте есть приложение и подключён
`domain` — правило выражено обязательными behavior:

- по одной behavior на каждый проверяемый аспект правила (детекция,
  реакция, хранение — по смыслу модуля);
- `check` — где проверку можно автоматизировать;
- новая фича, затрагивающая область правила, не считается готовой, пока
  связанные behavior не `verified: true`.

**Проверки.**

- правило есть в блоке `AGENTS.md` модуля, а не только в skill;
- у области правила в приложении есть хотя бы одна behavior;
- behavior правила с `verified: false` поднимается в каждом `report`
  как блокер, пока не проверена.

**Чего не делать.**

- не переносить правило в `context/conventions/` копией — оно живёт в
  блоке и skill модуля;
- не ослаблять правило ради сценария, дедлайна или просьбы «на этот
  раз»: исключение — только явным решением пользователя, записанным
  через docs-keeper.

## Провенанс

- `primary` — первоисточник: дословная речь, документ, книга автора;
- `secondary` — СМИ, чужой разбор, пересказ; атрибуция сверяется к
  вторичному тексту и не выдаётся за слова самого автора;
- `own` — моё утверждение из поста, позиции, заметки;
- `app-telemetry` — только при подключённом `app-loop`, семантика —
  skill `app-loop`.

Транспорт ≠ провенанс: книга, доставленная по каналу, остаётся
`primary` / `secondary`.

## Сущности

Все значения в примерах — синтетические. Реальные незрелые формулировки
моих позиций в примеры, логи и отчёты не попадают.

У `sources`, `claims`, `positions` — необязательное поле
`automated_by: [entity:<id>, behavior:<id>]` — формат ссылок skill
`app-loop`; только при подключённом `app-loop`.

### Источник — `analysis/sources/<id>.yml`

```yaml
id: speech-budget-a                # = путь внутри слоя
kind: source
namespace: process
summary: Выступление <политика A> о бюджете в парламенте
type: speech                       # quote | speech | document | article | book | note
provenance: primary                # primary | secondary | own
origin: <политик A>, пленарное заседание
locator_base: <URL стенограммы> · 2026-02-11
verified: true                     # оригинал доступен и подлинен
verified_at: 2026-02-12
verified_note: сверено со стенограммой на официальном сайте
claims: [budget-a-deficit-pledge]
```

`type: book` и поле `map` — по skill `book-corpus`.

### Тезис — `analysis/claims/<id>.yml`

```yaml
id: budget-a-deficit-pledge
kind: claim
namespace: process
summary: Обещание сократить дефицит без роста налогов за два года
provenance: primary
source: speech-budget-a            # для own — id позиции или поста
quote: "<дословная цитата>"        # необязательно; только сверенное
locator: стенограмма, абзац 14     # для own — пост/позиция + дата
verified: true                     # цитата и приписывание сверены
verified_at: 2026-02-12
verified_note: цитата сверена со стенограммой
tensions: [deficit-vs-spending]
```

### Позиция — `analysis/positions/<id>.yml`

```yaml
id: consent-legitimacy
kind: position
namespace: ideology
summary: Легитимность власти — из согласия управляемых
provenance: own                    # всегда
rationale: синтез чтения теорий договора; силовое обоснование отвергаю
reconciled: false
reconciled_at: null
reconciled_note: не сверено после state-of-nature-claim
claims: []
posts: [on-sovereignty]
tensions: []
```

### Пост — `analysis/posts/<id>.md`

```markdown
---
id: on-sovereignty
kind: post
namespace: ideology
provenance: own
positions: [consent-legitimacy]
reconciled: false
reconciled_at: null
reconciled_note: пересмотреть после разбора трактата о суверене
---

# О суверенитете

<эссе; ссылки на тезисы с локаторами>
```

### Разбор — `analysis/analyses/<id>.md`

Frontmatter как у поста, но `kind: analysis`, без `provenance`, плюс
`object` (что оценивается) и `draws_on` (источники, тезисы, позиции).
Тело — доказательная оценка на тезисах с локаторами, без риторики
вместо доказательства.

### Противоречие — `analysis/tensions/<id>.yml`

```yaml
id: deficit-vs-spending
kind: tension
namespace: process
summary: Обещание сократить дефицит против объявленного роста расходов
kind_of: cross                     # internal своё↔своё | external своё↔чужое | cross чужое↔чужое
sides: [budget-a-deficit-pledge, budget-a-spending-rise]
status: open                       # open | synthesized
note: null                         # подробности, если не влезли в summary
synthesis: null                    # как система развилась, если снято
```

Ссылки двусторонние: source ↔ claim, position ↔ post, tension ↔ его
стороны (`tensions` у каждой стороны).

## verified и reconciled

Три поля — три разных вопроса: субъективность (`own`) ≠ несверенная
атрибуция (`verified: false`) ≠ рассогласованность с базой
(`reconciled: false`).

- `verified` — у `sources` и `claims`: атрибуция сверена с оригиналом.
  `true` — только после свежей сверки, с `verified_at` и
  `verified_note`. Для `own` — сверена привязка к моему посту и дате.
- `reconciled` — у `positions`, `posts`, `analyses`: мой материал сверен
  на противоречия с текущей базой на дату.
  1. Приземлился новый релевантный тезис, позиция или изречение в том
     же namespace или теме — `reconciled: false` на затронутых, с
     `reconciled_note` «новые вводные: <id>».
  2. Пере-сверка — через диалектику: родилось противоречие — `tension`
     и предложение синтеза; нет — `reconciled: true` + дата.

## Диалектика

Мои позиции и посты — система отражения, а не свод догм; противоречие
в ней — точка роста. Шаг в `execute`, `challenge` и `inquiry`.

- **Двигатель, а не повод отбросить.** Нашёл напряжение — не выбирай
  сторону молча и не удаляй тезис: `tension` + предложение синтеза
  (система вбирает обе стороны или снимает противоречие на новом
  уровне).
- **Сохранение интента и steelman — симметрично.** Своя позиция,
  изречение политика, философский тезис — сначала в сильнейшей форме,
  с причиной, которая за ними стоит; потом критика. Соломенных чучел
  не строим.
- **Развитие, а не стирание.** Снятое противоречие —
  `status: synthesized` + `synthesis`; старая позиция задним числом не
  переписывается, `tension` не удаляется — это документ эволюции.
  Крупный синтез — ещё строка `[milestone]` в `CHANGELOG.md` через
  docs-keeper.

## Сценарий `inquiry`

Ключи: «найди», «что у нас есть про», «что я думаю о», вопрос по
существу.

1. Своя база: `context/index.yml` → namespace → нужные сущности.
   Найдено — ответ со ссылками на id и локаторы.
2. Пробел — назови его и эскалируй: внешний поиск (`curl`, web),
   глава книги (skill `book-corpus`, если подключён); новые `sources` /
   `claims` с провенансом и локаторами — через docs-keeper.
3. Индекс обновлён (`harness context index`; без harness — у новых
   сущностей есть `summary`): следующий виток видит добавленное.
4. Новая фактура касается моих взглядов — `reconciled` и диалектика.

В ответах — выводы и агрегаты; сырьё — по прямому запросу.

## Namespace

- новый — только с «да», сначала в `context/project.yml`; namespace —
  область анализа (`ideology`, `process-<name>`), не автор и не издание;
- больше ~30 сущностей одного вида в namespace — сигнал к дроблению,
  поднять в отчёте.

## Проверки

Перед сохранением:

- `id` = имя файла, `namespace` объявлен, `summary` / `# …` в одну
  строку;
- у тезиса есть `source` и `locator`; `quote` без сверки — нарушение;
- `verified: true` → `verified_at` заполнен и оригинал был доступен;
- после нового релевантного тезиса `reconciled: true` не остался на
  затронутых;
- у `tension` не меньше двух `sides`, ссылки двусторонние;
- `synthesized` без `synthesis` или с удалённой стороной — нарушение
  диалектики;
- `app-telemetry` и `automated_by` — только при подключённом `app-loop`.

`id`, namespace, `summary` / заголовок проверяет `harness check`
(`context-index`), если подключён harness.
