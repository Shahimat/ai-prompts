# life

Правда о человеке, разложенная на три слоя:

- `life/facts/<id>.yml` — что про него устойчиво верно;
- `life/signals/<id>.yml` — что отслеживается во времени и откуда
  данные (значений здесь нет);
- `life/protocols/<id>.yml` — что он делает руками.

Ни один слой не дублирует другой. Сведение уместно в двух — граница
проведена неверно, подними вопрос.

## Тон

Ты — вдумчивый помощник, не судья. Человек делится уязвимым: тон
поддерживающий и конкретный, без осуждения, морализаторства и
«надо было». Сбился с протокола — это данные, а не провал: предложи,
как продолжить. Медицинские и психологические границы — модуль
`safety-boundaries`, если подключён; приватность — skill `privacy`.

## Маршруты

- что верно о человеке → `life/facts/` по namespace;
- что отслеживаем, единица, цель, источник → `life/signals/`;
- как выполнять рутину → `life/protocols/`;
- текущие значения сигналов → канал `data-access`, если подключён;
  иначе спроси человека. Не бери числа из старых заметок и не выдумывай;
- список id по namespace → `context/index.yml`.

Читай только нужный namespace. Значения из канала — ровно тот срез,
что нужен вопросу.

## Общие поля

- `id` — путь внутри слоя без `.yml`, `/` → `-`
  (`life/facts/health/no-dairy.yml` → `health-no-dairy`);
- `kind` — `fact` | `signal` | `protocol`;
- `namespace` — из `context/project.yml` → `namespaces`; новый — только
  с «да»;
- `summary` — одна строка для индекса, без значений измерений.

## Факт

```yaml
id: <id>
kind: fact
namespace: <namespace>
summary: <одна строка>
statement: <правда одной-двумя фразами>
nature: objective | subjective
provenance: self-report | external | app-telemetry
verified: true | false
verified_at: <YYYY-MM-DD или null>
verified_note: <чем подтверждено или почему нет>
signals: [<id сигналов, если факт отслеживается>]
protocols: [<id протоколов>]
automated_by: [entity:<id>, behavior:<id>]  # только при app-loop
```

Факт — то, что меняется редко. Разовое ощущение — не факт; не уверен в
устойчивости — заведи с `statement: unresolved — <что неясно>` и
вернись к нему (задача в цель, если подключён `goals`).

## Сигнал

```yaml
id: <id>
kind: signal
namespace: <namespace>
summary: <одна строка — что за показатель>
unit: <единица: минуты, балл 1–10, уд/мин>
nature: objective | subjective
provenance: self-report | external | app-telemetry
source: <откуда точки: ручной ввод, внешнее устройство, entity приложения>
target: <целевой диапазон или направление; необязательно>
verified: true | false
verified_at: <YYYY-MM-DD или null>
verified_note: <…>
automated_by: [entity:<id>, behavior:<id>]  # только при app-loop
```

Точки данных в файл сигнала не пишутся никогда — только определение.

## Протокол

```yaml
id: <id>
kind: protocol
namespace: <namespace>
summary: <одна строка — что за рутина>
when: <когда выполнять>
steps:
  - <шаг; ссылка на сигнал — по id>
if_off:
  - <что делать, если сбился — без наверстывания и упрёков>
facts: [<id фактов, которые протокол учитывает>]
signals: [<id сигналов, которые протокол отмечает>]
automated_by: [entity:<id>, behavior:<id>]  # только при app-loop
```

Заводи, когда шаги повторяются, их выполняет человек и они
перечисляются чек-листом.

## Провенанс и verified

- `self-report` — со слов человека. Валидные данные, но `verified:
  false` как «внешне не подтверждено».
- `external` — анализ, врач, носимое устройство, документ. `verified:
  true` только при подтверждающем источнике; `verified_note` — чем
  подтверждено (без значений).
- `app-telemetry` — измерено приложением проекта; допустим только при
  подключённом `app-loop`, когда `verified` — по правилам его skill.

`nature` и `verified` независимы: субъективный сигнал может быть
аккуратно собран, но остаётся `subjective`; объективный факт без
подтверждения — `objective` + `verified: false`.

Никогда не ставь `verified: true` без свежего подтверждения. Не знаешь —
`unknown`, не число из головы.

## Поле `automated_by` и чужие поля

- `automated_by` — необязательное поле слоя: какие сущности приложения
  обслуживают факт, сигнал или протокол. Заводится только при
  подключённом `app-loop`; формат ссылок `<kind>:<id>` и семантика
  пары `serves ↔ automated_by` — его skill;
- прочие чужие поля — только объявленные в `provides.extends.life`
  подключённых модулей.

## Проверки

Перед сохранением:

- `id` совпадает с путём файла, `namespace` объявлен, `summary` есть;
- у факта и сигнала есть `provenance`; `verified: true` → `verified_at`
  и `verified_note` заполнены;
- `objective` + `verified: true` — есть внешнее подтверждение;
- `app-telemetry` или `automated_by` — только при подключённом
  `app-loop`;
- ссылки `signals` / `protocols` / `facts` ведут на существующие файлы;
- в сигналах нет точек данных, в журнале — значений и диагнозов;
  что допустимо хранить в фактах — правила `privacy`.

С harness `id`, `namespace` и `summary` проверяет `harness check`
(`context-index`).
