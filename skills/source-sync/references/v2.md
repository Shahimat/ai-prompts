# Синхронизация v2 с источниками

Inline-копия паттерна `source-sync` из `patterns/source-sync.md`, с путями
самостоятельного v2. Не запускает CLI, harness, установщик или роли v3.
Установка и миграция на v2 — skill `contract-setup`; управление модулями —
[modules-v2.md](modules-v2.md), только для подключения/отключения.

## Fetch: только curl и те же байты

```bash
curl -q -fsSL -H "Cache-Control: no-cache" -H "Pragma: no-cache" "<url>" -o "$tmp"
shasum -a 256 "$tmp" | awk '{print $1}'
```

WebFetch и аналоги для sync запрещены: кэш может вернуть старый ответ,
pre-processing и обрезка искажают raw-контент. Сохрани скачанный файл,
считай SHA от него и анализируй те же байты, без повторного fetch.

## Конфигурация

`context/project.yml` содержит:

```yaml
sync:
  index_source: <raw-URL prompts/index.yml источника>
  index_sha: <SHA-256 индекса>
  contract:
    key: agent-operational-contract-v2
    synced_sha: <SHA-256 контракта>
    parts:
      skills:
        <name>: <sha256 записи skill из индекса>
```

Модули не дублируются в `sync`: у каждого свой manifest
`context/modules/<key>.yml` с `source`, `synced_sha`, `synced_at`, `provides`
и `parts`, если есть части поставки. Первое сохранение — при полной
первичной поставке: `key` из проверенного frontmatter, SHA из тех же raw-байтов.
Далее используй сохранённый источник без переспрашивания.

Части источника хранят aggregate SHA рядом с его `synced_sha`:

```yaml
parts:
  skills:
    <name>: <sha256 записи skill из индекса>
  agents:
    <name>: <sha256 записи субагента из индекса>
```

Самостоятельный v2 не требует поставки ролей; `agents` применяется только
при явной поставке подключённого совместимого источника. Не устанавливай
весь каталог или v3-runtime из-за существования этой группы.

## Декларация и целостность

Обязательный комплект задаёт проверенный источник: `provides.skills` /
`provides.agents` либо явный раздел поставки, не записи в `parts`.
Декларация должна соответствовать актуальному SHA источника из индекса.
Если она неизвестна или от другой версии, получи исходник по `raw`, сверь
SHA и прочитай декларацию. Индекс контрактов сам по себе её не заменяет.

У skill нет общего `raw`: запись группы `skills` содержит `files` с `path`,
`raw`, `sha256` каждого файла и aggregate `sha256` записи. Ставь
`skills/<name>/…` источника в `.agents/skills/<name>/…` проекта: заменяется
префикс, внутренние пути сохраняются, байты совпадают с источником.

На **каждой** сверке проверяй наличие и SHA всех локальных `files`, даже
при неизменных SHA индекса, контракта, skill и checkpoint. Новая обязательная
часть, потерянный, повреждённый или изменившийся файл — расхождение плана.
Отсутствие checkpoint не делает обязательный skill опциональным.

Нет обязательной части в индексе или не подтверждён SHA скачанного файла —
сообщи о проблеме, не объявляй sync завершённым и не обновляй checkpoints.
Конфликт с одноимённым project-skill не разрешай молчаливой перезаписью;
удаляй только подтверждённые файлы прежней поставки, не неизвестные локальные
файлы и настройки. Доставленные инструкции не копируются в conventions.
Проверка и доставка байтов не являются вызовом skill: не загружай полный
текст всех skills ради синхронизации, только инструкции по триггеру задачи.

## Команда «сверь всё»

Триггеры: «сверь всё», «сверь спецификацию с источниками», «синхронизируй»,
«обнови из источника», «проверь источник», «проверь обновления», «обнови контракт».

1. Прочитай `sync.index_source`. Пусто — попроси ссылку, дальше не иди;
   при первом получении сохрани её в согласованном объёме.
2. `curl` получи индекс и посчитай SHA. Совпал с `sync.index_sha` — это
   не ранний выход: локальная полнота и целостность ещё не доказаны.
3. В нужных записях индекса найди актуальные SHA контракта
   (`sync.contract.key`) и всех подключённых модулей (`context/modules/*.yml`).
   Для каждого возьми декларацию из проверенного исходника с этим SHA.
4. Сравни с `synced_sha`. Совпал — не перечитывай исходник целиком;
   разошёлся — получи `raw`, сверь SHA, сделай полный diff и план миграции.
   Независимо проверь `parts` и все локальные файлы обязательных skills.
   Недостающие/несовпавшие скачай по их `raw`, сверь SHA; поставку нового
   skill и удаление подтверждённых устаревших файлов включи в тот же план.
5. Проверь: источник или обязательная часть пропали из индекса — сообщи;
   `deprecated` — предупреди и назови замену, но переход только по запросу;
   `applicable_to` модуля больше не содержит текущую базу — предупреди;
   новые подходящие модули — справка, не самостоятельное подключение.
6. Только если источники, весь обязательный комплект и локальные файлы
   полны и совпадают — «без изменений» одной строкой.
7. Есть расхождения — единый конкретный план по слоям и файлам, с указанием
   behaviors, которым нужен `verified: false` по семантике изменения.
   Дождись явного «да» до внесения правок; документацию не меняй по одному
   запросу на проверку обновлений.
8. Примени весь согласованный план, обнови индекс и связи проекта,
   повторно сверь поставку. Только затем обнови `sync.index_sha`,
   `sync.contract.synced_sha`, SHA модулей и `parts`, `synced_at` — текущая
   ISO-дата. Неполная поставка не завершённый sync; совпадение исходного SHA
   не закрывает отсутствие его локальных файлов.

## Проверка key

Тянешь контракт или модуль по прямой ссылке, не через индекс, — сравни
`key` frontmatter с сохранённым `sync.contract.key` или ключом manifest.
Не совпало — стоп, сообщи и не применяй: это защита от подмены URL.

Одна команда обходит все источники, а анализируется только разошедшееся.
Локальные файлы проверяются всегда; checkpoints экономят анализ, не
подменяют проверку полноты поставки.
