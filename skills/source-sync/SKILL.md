# source-sync

Применение паттерна `source-sync` (см. `patterns/source-sync.md` в
репозитории `ai-prompts`), расширенное для v3: отчёт «Что нового» и
версия harness. Механика SHA обновляется вместе с паттерном.

## Единый fetch-канал: только `curl`

<!-- expect:curl-only -->
```bash
curl -fsSL -H "Cache-Control: no-cache" -H "Pragma: no-cache" "<url>" -o "$tmp"
shasum -a 256 "$tmp" | awk '{print $1}'
```

WebFetch и аналоги запрещены: кэш инструмента подставляет старый ответ,
pre-processing (HTML → markdown, обрезка) искажает контент, и SHA не
сойдётся с raw-контентом источника. Скачанный файл сохраняй и работай
с ним, без повторного fetch.
<!-- /expect:curl-only -->

## Конфигурация проекта

`context/project.yml`:

```yaml
sync:
  index_source: <raw-URL prompts/index.yml источника>
  index_sha: <hex — SHA-256 индекса на момент последней синхронизации>
  contract:
    key: agent-operational-contract-v3
    synced_sha: <hex>
    parts:
      skills: {<name>: <hex>}
      agents: {<name>: <hex>}
```

Manifest каждого модуля — `context/modules/<key>.yml` со своими
`source`, `synced_sha`, `synced_at`, `provides` и `parts`; в `sync`
проекта модули не дублируются.

Части источника — skills (`skills/<name>/` в источнике) и субагенты
(`agents/<name>.md`) — хранят SHA в `parts` рядом с SHA источника. В
индексе у skill нет общего `raw`: запись содержит `files` с `raw` и
`sha256` каждого файла, `sha256` записи меняется при правке любого
файла.

Свои расширения проекта в `.agents/` — роли, команды, скрипты,
автоматы, которых нет в `parts`, — обновление не трогает и не удаляет.
Совпало имя своей роли с новой ролью источника — стоп, вопрос
пользователю.

## Обновление из источника

<!-- expect:sync-warns-deprecated -->
Ключи: «проверь обновления», «что нового в источнике», «обнови контракт»,
«синхронизируй», «обнови из источника».

1. Прочитай `sync.index_source`. Пусто — «источник не сохранён, пришли
   ссылку», дальше не идёшь. Получил ссылку — сохрани.
2. Процесс harness:
   <!-- expect:skill-runs -->
   <!-- metadata.runs: source-sync -->
   Если подключён harness — сценарий ведёт `ai source-sync
   start`. Он печатает текущую версию из `context/ai-core.yml`, последнюю
   в npm и записи журнала пакета между ними (всегда, даже если индекс не
   менялся), и останавливается с заданием: шаги 3–8. После них —
   `ai source-sync open <id>`: harness пересоберёт адаптеры и
   `context/index.yml` и проверит проект; провал вернёт задание.
   <!-- /expect:skill-runs -->
3. `curl` тянет `index.yml`, считай SHA-256. Совпал с `sync.index_sha` и
   harness актуален — «без изменений», выход (с harness — resume).
4. Не совпал — читай индекс. Источники: контракт (`sync.contract.key`)
   и модули (`context/modules/*.yml`); для каждого — его `parts`.
5. Сравни `sha256` из индекса с сохранёнными:
   - совпал — пропускаешь;
   - разошёлся у контракта или модуля — `curl` тянет файл по `raw`,
     полный diff, план миграции;
   - разошёлся у skill — тянешь только файлы, чей `sha256` в `files` не
     совпал с локальной копией в `.agents/skills/<name>/`; файлы,
     которых больше нет в `files`, — к удалению;
   - разошёлся у субагента — тянешь файл по `raw`.

   SHA каждого скачанного файла сверяешь с индексом. Не совпал — стоп.
6. Дополнительно:
   - подключённый модуль, skill или субагент пропал из индекса —
     предупреди;
   - контракт или модуль помечен в индексе `deprecated` — предупреди и
     назови замену (ключ или путь из поля), миграция — по запросу;
   - `applicable_to` модуля больше не содержит
     `agent-operational-contract-v3` — предупреди;
   - контракт поменял список своих skills или субагентов — новые
     поставить, исчезнувшие удалить (в план).
7. Отчёт «Что нового» (ниже) и один блокирующий вопрос.
8. После «да»: применяешь план к артефактам контракта — `.agents/`,
   блоки `AGENTS.md`, manifest'ы `context/modules/`, блок `sync` в
   `context/project.yml`; правки слоёв документации проекта — только
   через docs-keeper. Затем обнови `sync.index_sha`, `synced_sha`
   контракта и модулей, SHA в `parts`, `synced_at`; при обновлении
   harness — `version` в `context/ai-core.yml`. Адаптеры и проверку с
   harness делает resume процесса (шаг 2), без harness — вручную.
<!-- /expect:sync-warns-deprecated -->

## Отчёт «Что нового»

<!-- expect:update-report -->
Коротко, по разделам; пустой раздел не выводится:

- **Контракт и подключённые модули** — что изменилось, по строке на
  источник, и план миграции.
- **Новые модули** — подходящие по `applicable_to` и не подключённые:
  `title` и `feature.summary` из индекса.
- **Устаревшие и пропавшие** — `deprecated` с заменой, исчезнувшие из
  индекса.
- **Новые пресеты** — группа `presets` индекса, которых не было при
  прошлой сверке.
- **harness** — версия проекта → последняя и записи журнала между ними
  из первого шага процесса: новые команды и проверки.

Вопрос в конце — нумерованные варианты:

1. применить план обновления (и обновить harness, если отстал);
2. открыть чеклист `contract-setup` — включить новые или отключить
   ненужные возможности;
3. только отчёт, ничего не менять.

Сам ничего не подключаешь и не отключаешь: выбор — за пользователем.
<!-- /expect:update-report -->

## Проверка `key`

Тянешь контракт или модуль по прямой ссылке, не через индекс, — `key`
из frontmatter должен совпасть с сохранённым (`sync.contract.key` или
manifest модуля). Не совпал — стоп, не применяй: защита от подмены URL.

## Смысл

Одна просьба вместо пересылки ссылок. SHA-checkpoint экономит
токены: из десяти источников менялся один — читаешь и анализируешь
только его.
