# contract-setup

Сначала выбери целевой контракт, затем прочитай **только его протокол**:

- v2.1 — [references/v2-1.md](references/v2-1.md): greenfield, brownfield
  и миграция с v2 в раскладку `.oc/`;
- самостоятельный v2 — [references/v2.md](references/v2.md): greenfield,
  brownfield, миграция точки входа и критерии полного перехода;
- v3, включая явный переход v2 → v3 —
  [references/v3.md](references/v3.md): пресеты, возможности и их подключение.

Целевую версию задаёт запрос пользователя; для изменения установленного
контракта сверь `AGENTS.md` и `sync.contract.key` в `context/project.yml`
или `.oc/project.yml`. Старый каталог или архив
не выбирает версию. Если цель неясна или инструкции расходятся — уточни
до правок, не выбирай v3 молча. Переход v2 → v2.1 и v2 → v3 — отдельные решения.

Не читай все протоколы «на всякий случай». Ссылки внутри reference считаются
относительно этого файла. Для v2 и v2.1 не нужны роли, harness, `.oc3/` или
пресет v3; CLI нужен только v2.1 — `@shahimat/cli` с командой `ai data check`;
`metadata.runs: refresh` относится только к протоколу v3.

Управление модулями v2, необязательными skills v2.1 и проверка файлов
поставки — skill `source-sync`.
Схемы очереди — `goals`, человеческие процедуры — `manuals`: загружай их
только при соответствующей части установки или миграции.
