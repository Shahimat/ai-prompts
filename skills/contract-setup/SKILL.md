# contract-setup

Возможности — модули источника `ai-prompts` с `applicable_to`,
содержащим `agent-operational-contract-v3`, и блоком `feature`. Этот
skill — протокол их выбора, подключения и отключения.

## Шаг 1. Каталог

1. `curl` тянет индекс по `sync.index_source` из `context/project.yml`
   (правила fetch — skill `source-sync`).
2. Из группы `modules` возьми записи, у которых `applicable_to`
   содержит `agent-operational-contract-v3` и есть `feature`.
3. Подключённые сейчас — `context/modules/*.yml`.

## Шаг 2. Пресет

<!-- expect:preset-first -->
Это первый вопрос пользователю в contract-setup — до чеклиста и уточнений.

Из группы `presets` индекса возьми записи с `applicable_to`, содержащим
`agent-operational-contract-v3`. Вопрос: «пресет или вручную» —
варианты: пресеты (`title`) и «вручную». Выбран пресет — `curl`
тянет его по `raw`, сверь `sha256`; его `modules` становятся отметками
чеклиста, а `answers` — дефолтами вопросов `asks`. Пресет — стартовая
точка: пользователь правит отметки и ответы как обычно. Ключ пресета
запиши в `context/project.yml` → `preset`.
<!-- /expect:preset-first -->

## Шаг 3. Чеклист

<!-- expect:checklist-fallback -->
Один вопрос с выбором нескольких вариантов:

- пункт — `title` модуля + `feature.summary`;
- отмечено: при установке — по пресету или `feature.default`, повторно —
  то, что подключено сейчас;
- есть инструмент вопроса с multi-select — используй его; нет —
  нумерованный список, отмеченные помечены `[x]`, ответ — номерами
  через запятую.
<!-- /expect:checklist-fallback -->

## Шаг 4. Зависимости

<!-- expect:extends-only -->
- `requires`: выбран модуль, а то, что он требует, — нет → добавь
  требуемое и скажи об этом одной строкой.
- `conflicts`: выбраны конфликтующие модули → стоп, блокирующий вопрос.
- `extends`: два выбранных модуля добавляют одно и то же поле в один
  слой → конфликт, стоп и вопрос. Расширяемый модуль (`domain`,
  `goals`, …) не выбран → требуй его, как `requires`.
- Снята галочка с модуля, который требуется другому выбранному, → стоп,
  вопрос.
<!-- /expect:extends-only -->

## Шаг 5. Уточнения

Для каждого нового модуля: `curl` тянет его по `raw` из индекса, сверь
`sha256` и `key`. Задай вопросы из `feature.asks` — одним блоком на все
модули. Вопрос с `multi: true` — тоже чеклистом.

## Шаг 6. Подключение

<!-- expect:module-install -->
<!-- expect:module-tags -->
По одному модулю; модуль — отдельный шаг с отчётом (skill `workflow`).

1. Прочитай модуль: он описывает, что ставит, с учётом ответов на
   `asks`.
2. План: какие файлы, слои, skills, блок `AGENTS.md`. Жди «да».
3. Поставь:
   - файлы и слои из раздела модуля «Что ставит»;
   - skills модуля из индекса — в `.agents/skills/<name>/`, байт в
     байт, SHA каждого файла сверен;
   - блок в конец `AGENTS.md` между `<!-- module:<key> -->` и
     `<!-- /module:<key> -->` — текст из модуля;
   - строки `gitignore` модуля — в `.gitignore`, если их там нет.
4. Manifest `context/modules/<key>.yml`:

   ```yaml
   key: <key>
   source: <raw-URL модуля>
   synced_sha: <sha256 модуля из индекса>
   synced_at: <YYYY-MM-DD>
   answers:                         # ответы на feature.asks
     <ask-key>: <значение или список>
   provides:
     layers: [<каталоги-слои>]
     files: [<файлы>]
     skills: [<имена skills>]
     agents_md_block: true
     harness_checks: [<ключи проверок в context/ai-core.yml>]
     changelog_tags: [<теги журнала решений модуля>]
     gitignore: [<строки, добавленные в .gitignore>]
     extends:                       # поля в слоях других модулей
       <модуль>: [<поля>]
     index_layers:                  # слои для context/index.yml, если есть
       - section: <имя секции>
         dir: <каталог слоя>
   parts:
     skills:
       <name>: <sha256 записи skill из индекса>
   ```

5. `changelog_tags` модуля — допиши в `context/ai-core.yml` →
   `checks.changelog.tags`, если подключён harness (список ядра плюс
   теги модулей).
6. Адаптеры, индекс и проверки:
   <!-- expect:skill-runs -->
   <!-- metadata.runs: refresh -->
   `ai refresh`, если подключён harness; иначе обнови производные
   файлы сам (`AGENTS.md` → «Адаптеры» ядра).
   <!-- /expect:skill-runs -->
<!-- /expect:module-tags -->
<!-- /expect:module-install -->

## Шаг 7. Отключение

1. Прочитай manifest, покажи всё из `provides`, что будет удалено:
   слои, файлы, skills, блок `AGENTS.md`, проверки и теги в
   `context/ai-core.yml`, строки `gitignore` (если их не объявляет
   другой модуль), поля `extends` в чужих слоях (записи в
   CHANGELOG с тегами модуля остаются — журнал не переписывается).
2. Слой с содержимым проекта (entities, manuals, цели) — отдельный
   вопрос: удалить или оставить как обычные файлы проекта.
3. После «да» — удали, убери блок из `AGENTS.md`, удали manifest,
   обнови адаптеры.

## Конфликты provides

Два модуля объявляют один и тот же слой, файл или skill — конфликт.
Не сливай молча: стоп, варианты — отключить один, развести вручную,
попросить автора модуля.

## Граница модуля

Модуль только добавляет: слои, файлы, skills, блок `AGENTS.md`,
проверки harness, теги журнала, поля в чужих слоях через `extends`.
Модуль не меняет правила ядра, чужие блоки `AGENTS.md` и не
переопределяет поля других модулей. Нужно изменить ядро — это правка
контракта в источнике, не модуль.
