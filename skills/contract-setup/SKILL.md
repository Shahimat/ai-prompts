# contract-setup

Сначала выбери целевой контракт, затем прочитай **только его протокол**:

- самостоятельный v2 — [references/v2.md](references/v2.md): greenfield,
  brownfield, миграция точки входа и критерии полного перехода;
- v3, включая явный переход v2 → v3 —
  [references/v3.md](references/v3.md): пресеты, возможности и их подключение.

Целевую версию задаёт запрос пользователя; для изменения установленного
контракта сверь `AGENTS.md` и `sync.contract.key`. Старый каталог или архив
не выбирает версию. Если цель неясна или инструкции расходятся — уточни
до правок, не выбирай v3 молча. Переход v2 → v3 — отдельное решение.

Не читай оба протокола «на всякий случай». Ссылки внутри reference считаются
относительно этого файла. Для v2 не нужны роли, CLI, harness, `.oc3/` или
пресет v3; `metadata.runs: refresh` относится только к протоколу v3.

Управление модулями v2 и проверка файлов поставки — skill `source-sync`.
Схемы очереди — `goals`, человеческие процедуры — `manuals`: загружай их
только при соответствующей части установки или миграции.
