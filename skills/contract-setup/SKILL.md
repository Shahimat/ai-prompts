# contract-setup

Возможности — модули источника `ai-prompts` с `applicable_to`,
содержащим `agent-operational-contract-v3`, и блоком `feature`. Этот
skill — протокол их выбора, подключения и отключения.

## Шаг 1. Каталог

1. `curl` тянет индекс по `sync.index_source` из `context/project.yml`
   (правила fetch — skill `source-sync`).
2. Из группы `modules` возьми записи, у которых `applicable_to`
   содержит `agent-operational-contract-v3` и есть `feature`.
3. Подключённые сейчас — `context/modules/*.yml`.

## Шаг 2. Чеклист

Один вопрос с выбором нескольких вариантов:

- пункт — `title` модуля + `feature.summary`;
- отмечено: при установке — по `feature.default`, повторно — то, что
  подключено сейчас;
- есть инструмент вопроса с multi-select — используй его; нет —
  нумерованный список, отмеченные помечены `[x]`, ответ — номерами
  через запятую.

## Шаг 3. Зависимости

- `requires`: выбран модуль, а то, что он требует, — нет → добавь
  требуемое и скажи об этом одной строкой.
- `conflicts`: выбраны конфликтующие модули → стоп, блокирующий вопрос.
- Снята галочка с модуля, который требуется другому выбранному, → стоп,
  вопрос.

## Шаг 4. Уточнения

Для каждого нового модуля: `curl` тянет его по `raw` из индекса, сверь
`sha256` и `key`. Задай вопросы из `feature.asks` — одним блоком на все
модули. Вопрос с `multi: true` — тоже чеклистом.

## Шаг 5. Подключение

По одному модулю; модуль — одна фаза с точкой согласования.

1. Прочитай модуль: он описывает, что ставит, с учётом ответов на
   `asks`.
2. План: какие файлы, слои, skills, блок `AGENTS.md`. Жди «да».
3. Поставь:
   - файлы и слои из раздела модуля «Что ставит»;
   - skills модуля из индекса — в `.agents/skills/<name>/`, байт в
     байт, SHA каждого файла сверен;
   - блок в конец `AGENTS.md` между `<!-- module:<key> -->` и
     `<!-- /module:<key> -->` — текст из модуля.
4. Manifest `context/modules/<key>.yml`:

   ```yaml
   key: <key>
   source: <raw-URL модуля>
   synced_sha: <sha256 модуля из индекса>
   synced_at: <YYYY-MM-DD>
   answers:                         # ответы на feature.asks
     <ask-key>: <значение или список>
   provides:
     layers: [<каталоги-слои>]
     files: [<файлы>]
     skills: [<имена skills>]
     agents_md_block: true
     harness_checks: [<ключи проверок в context/harness.yml>]
     index_layers:                  # слои для context/index.yml, если есть
       - section: <имя секции>
         dir: <каталог слоя>
   parts:
     skills:
       <name>: <sha256 записи skill из индекса>
   ```

5. Адаптеры: `harness adapters sync`, если подключён harness; иначе
   обнови производные файлы сам (`AGENTS.md` → «Адаптеры» ядра).
6. Если harness подключён — `harness check`.

## Шаг 6. Отключение

1. Прочитай manifest, покажи всё из `provides`, что будет удалено:
   слои, файлы, skills, блок `AGENTS.md`, проверки в
   `context/harness.yml`.
2. Слой с содержимым проекта (entities, manuals, цели) — отдельный
   вопрос: удалить или оставить как обычные файлы проекта.
3. После «да» — удали, убери блок из `AGENTS.md`, удали manifest,
   обнови адаптеры.

## Конфликты provides

Два модуля объявляют один и тот же слой, файл или skill — конфликт.
Не сливай молча: стоп, варианты — отключить один, развести вручную,
попросить автора модуля.

## Граница модуля

Модуль только добавляет: слои, файлы, skills, блок `AGENTS.md`,
проверки harness. Модуль не меняет правила ядра, чужие блоки
`AGENTS.md` и файлы других модулей. Нужно изменить ядро — это правка
контракта в источнике, не модуль.
