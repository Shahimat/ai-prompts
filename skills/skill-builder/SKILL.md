# skill-builder

## Согласование

<!-- expect:skill-builder -->
Создавай и меняй skills только по явному согласованию с пользователем.
Оно относится к конкретному skill и объёму; прямого поручения достаточно.
Общий запрос на фичу не даёт такого разрешения. За проход — один skill
с его references и подключениями; следующий — после отдельного согласования.

## Текст

Один skill — одно назначение. В `SKILL.md` оставляй триггер и правила;
детали — в references по необходимости. Имя каталога и `name` совпадают
(kebab-case); `description` объясняет назначение и условия загрузки.
Не дублируй проектные факты и правила из их канонических файлов.

По умолчанию — абзацы. Нумерованный список — только последовательность
взаимосвязанных действий с важным порядком; ненумерованный — только
обязательные действия без заданного порядка. Иные списки не используй.
Синтаксис и шаблоны показывай code blocks.

## Подключение

В ai-prompts канон — `skills/<name>/`, в проекте — `.agents/skills/<name>/`.
Поставляемый skill объяви в `provides.skills` контракта или модуля,
обнови маршрут загрузки и индекс (в ai-prompts — `prompts/index.yml`).
Установка и SHA — по `contract-setup`/`source-sync`, без попутного
редактирования поставляемых инструкций.

- Проверь frontmatter, ссылки, непротиворечивость правил и назначение списков.
- Проверь объявление зависимости, загрузку нужной версии и SHA файлов.

В отчёте укажи результат и границы проверки.
