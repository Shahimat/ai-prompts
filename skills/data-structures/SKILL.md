# data-structures

Структура данных — проектный способ хранить однотипные факты: снимки
рекламных кампаний, кейсы для резюме, ссылки на внешние системы, компоненты
своей системы. Универсального набора структур нет: каждый проект заводит свои
под предметную область, а этот skill — правила их создания и изменения. Чтение
готовых записей идёт по маршруту из `AGENTS.md` и этого skill не требует.

## Раскладка

```text
.oc/data/<key>/
  schema.json     JSON Schema 2020-12 на одну запись, с описаниями полей
  index.yaml      назначение структуры, указатель на skill, список записей
  <id>.yml        записи, плоско в каталоге структуры
```

Записи не раскладываются по подкаталогам: одна структура — один вид записей.
Вложенные каталоги и файлы прямо в `.oc/data/` команда проверки отвергает.

## Схема

`schema.json` описывает одну запись. Обязательное поле — `id` (kebab-case,
совпадает с именем файла без `.yml`); у остальных полей заполняйте
`description`: по ним запись читают без загрузки skills. Лишние поля
запрещайте (`additionalProperties: false`) — так «уплывшие» поля ловятся
проверкой, а не глазом. Общие фрагменты выносите в соседние файлы
`*.schema.json` и подключайте по `$ref` с именем файла. Даты и периоды
записывайте строками в кавычках.

## Индекс структуры

`index.yaml` ведётся руками и обновляется в том же изменении, что и записи:

```yaml
key: ads-snapshots            # совпадает с именем каталога
title: Снимки рекламных кампаний
summary: Показы, клики, целевые визиты и расход по периодам — для решений о ставках
namespace: promotion          # необязательно; одно из namespaces в .oc/project.yml
skill: ads-metrics            # необязательно; skill с правилами работы с записями
records:
  - id: 2026-01-06-campaign-a
    file: 2026-01-06-campaign-a.yml
    summary: Первая неделя пилота — 96 кликов, 2 целевых визита
```

`title` и `summary` — то, по чему общий индекс и план решают, подходит ли
структура. `namespace` привязывает структуру к области проекта, когда структур
много; берётся из `namespaces` в `.oc/project.yml`. `skill` указывает на skill
с правилами интерпретации и свежести записей, если они нужны; у большинства
структур его нет. Список `records` может быть пустым. В значениях без кавычек
последовательность «двоеточие и пробел» ломает YAML — пишите тире или берите
значение в кавычки.

## Общий индекс

Новая структура в том же изменении вносится в секцию `data` общего индекса
`.oc/index.yml` — строкой с `key`, путём до её `index.yaml` и однострочным
`summary`. Отдельные записи общий индекс не перечисляет: их список живёт в
структуре.

## Развилка на входе plan

Прежде чем планировать работу с фактами, посмотрите секцию `data` общего
индекса и `index.yaml` с `schema.json` подходящей структуры. Структура
подходит — записи добавляются и правятся по действующей схеме в пределах
согласованного тикета. Полей не хватает — расширение схемы является
изменением договора структуры: предложите, какие поля добавить, зачем и что
будет с существующими записями, и дождитесь явного «да». Подходящей структуры
нет — предложите новую с ключом, назначением, полями, `namespace` и
потребностью в `skill` и тоже дождитесь «да».

Факт живёт в одной структуре. Не складывайте данные в manuals, очередь goals,
тексты skills и README и не заводите структуру ради разового факта, который
не пригодится следующему участнику. Секреты и личные данные в записи не
попадают — вместо значения указатель на хранилище.

## Проверка

После любого изменения в `.oc/data/` или секции `data` общего индекса
выполняйте из корня проекта:

```bash
ai data check
```

Команда доступна, если в проекте стоит `@shahimat/cli`. Она сверяет: схема
компилируется; `index.yaml` соответствует своему формату; каждая запись
проходит по своей схеме; записи и `records` индекса ссылаются друг на друга
без пропусков и дублей; структуры и секция `data` общего индекса совпадают.
Ненулевой код возврата — исправьте до «Готово»: прогон входит в готовность
тикета.

## Имена и границы

Ключ структуры — стабильный kebab-case, отражающий предмет (`ads-snapshots`,
`resume-cases`, `external-links`), а не `data`, `misc` или `notes`.
Идентификатор записи — kebab-case, равный имени файла. Не смешивайте в одной
структуре разные виды записей: если поля расходятся от записи к записи, это
повод либо объявить поле в схеме явно, либо разделить структуру.

## Проверяемые утверждения

Если записи утверждают то, что можно проверить (поведение системы,
состояние внешнего сервиса), добавьте в схему `verified` (логическое),
`verified_at` (дата или `null`) и `verified_note` (чем проверено или что
мешает). `verified: true` ставится только после свежей проверки. Это выбор
проекта, а не требование контракта.

## Пример

`schema.json`:

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "Снимок рекламной кампании за период",
  "type": "object",
  "additionalProperties": false,
  "required": ["id", "campaign", "period", "impressions", "clicks", "cost_rub"],
  "properties": {
    "id": { "type": "string", "pattern": "^[a-z0-9]+(-[a-z0-9]+)*$" },
    "campaign": { "type": "string", "description": "Идентификатор кампании в кабинете" },
    "period": { "type": "string", "description": "Диапазон дат ISO: YYYY-MM-DD–YYYY-MM-DD" },
    "impressions": { "type": "integer", "minimum": 0, "description": "Показы за период" },
    "clicks": { "type": "integer", "minimum": 0, "description": "Клики за период" },
    "cost_rub": { "type": "number", "minimum": 0, "description": "Расход за период, рубли" },
    "goal_visits": {
      "type": "object",
      "additionalProperties": { "type": "integer", "minimum": 0 },
      "description": "Целевые визиты по имени цели счётчика"
    },
    "source": { "type": "string", "description": "Откуда сняты цифры и когда проверены" },
    "finding": { "type": "string", "description": "Вывод по периоду одной-двумя фразами" }
  }
}
```

Запись `2026-01-06-campaign-a.yml`:

```yaml
id: 2026-01-06-campaign-a
campaign: campaign-a
period: "2026-01-06–2026-01-12"
impressions: 1540
clicks: 96
cost_rub: 2880.5
goal_visits:
  phone: 1
  calculator: 1
source: "Кабинет рекламной сети, выгрузка 2026-01-13"
finding: Охват ограничен географией, ставку не повышать.
```

## Связи

Факты — в структурах, процедуры для человека — в manuals по skill `manuals`,
оставшаяся работа — в очереди по skill `goals`, правила — в skills; куда что
записывать в целом — skill `project-docs`. Повторяющиеся правила работы со
структурой выносятся в skill (проектный — через `skill-builder`), и
`index.yaml` указывает на него в поле `skill`.
