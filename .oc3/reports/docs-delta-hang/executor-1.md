# docs-delta-hang — отчёт executor (цикл 1)

## Диагноз

1. «start --file -» вис на чтении stdin: `stdinText()` ждал EOF без
   таймаута — при TTY или незакрытом писателе процесс не отвечал вечно;
   сессия при этом не создавалась.
2. «open» вис в `opsRole`: ожидание слота или rate-limit backoff —
   бесконечный цикл сна без причины в выводе и без предела; общий
   `backoff.json` в домашнем реестре (~/.config/harness) держал паузу до
   30 мин на каждый заход.
3. После ручного снятия процессов протухшая сессия (a7267f) оставалась в
   реестре ~/.config/harness/sessions — штатной команды снятия не было.

## Что сделано

- ai-core `lib/intents.ts`: stdin — терминал или тишина без данных —
  быстрая ошибка с причиной; таймаут env `HARNESS_STDIN_TIMEOUT_S`
  (по умолчанию 10 с), поток разрушается при ошибке — процесс не
  остаётся висеть.
- harness `ops/runner.ts`: `opsRole` принял `waitMin` — предел ожидания
  слота/backoff с ошибкой «ожидание превысило …» и причиной; прогресс
  ожидания (причина + остаток) в stderr, без спама. Шаги автоматов
  (`sessionRole`) включают лимит: env `HARNESS_STEP_WAIT_MIN`, по
  умолчанию 5 мин; фоновые lane'и ops (watch/tick) ждут как раньше.
- harness `store/session.ts` + `core/catalog.ts`: `list --stale
  [--days <дней>]` — протухшие сессии своего harness (порог по
  последней записи журнала; env `HARNESS_STALE_DAYS`, по умолчанию 7;
  сессии с живой ролью не показываются), `open <id> --forget` — снятие
  с учёта (удаление каталога сессии из реестра; отказ, пока роль жива —
  pid виден). Поверхность команд не расширялась: только флаги
  объявленных `list`/`open` — expectations не тронуты.
- cli: разбор флагов `--stale`, `--days`, `--forget`.
- Релизный каскад: ai-core 0.1.6 → 0.1.7 (первая публикация каскада),
  пины ai-core в cli (0.1.4, неопубликованная), harness (0.5.0,
  неопубликованная) и oc3 (0.1.3, опубликованная) подняты на 0.1.7;
  package-lock синхронизирован; `packages-check` — критичных 0, только
  штатные «требуется публикация».
- Тесты: `stale.test.ts` (поиск/порог/снятие/отказ при живой роли),
  `ops.test.ts` (waitMin — ошибка и прогресс), `docs-delta-roles.test.ts`
  (молчащий stdin — код 2 за таймаут, сессия не создана).

## Отклонение от плана (граница)

`npm run ci` красный ровно на одном crit — «верхняя запись CHANGELOG.md
пакета — его текущая версия»: для ai-core 0.1.7 нужна запись в
`packages/ai-core/CHANGELOG.md`. Правка CHANGELOG агенту executor
запрещена (правило 4 AGENTS.md; в этой сессии правку отклонил guard
сессии — уточнение по вердикту judge: docs guard плагина oc3 прикрывает
только корневой CHANGELOG). Текст записи передан в отчёт для
librarian; после его записи ci зелёный без прочих изменений.

Заготовка записи для librarian (packages/ai-core/CHANGELOG.md, сверху):

```markdown
## 0.1.7

- Канал итога роли доводит ответ до harness: конверт `{message, data}` и голый массив ответов батча
  разбираются из текста, итог берётся и из файла сессии `.ops/submit/<id>.json`, отказ называет
  причину и путь транскрипта.
- `expect judge --run` пишет транскрипты прогона судьи в `expectations/.judge/transcripts/`
  (каталог переопределяется env `HARNESS_EXPECT_TRANSCRIPT`).
- `--file -` не висит на молчащем stdin: терминал и пауза без данных — быстрая ошибка (таймаут —
  env `HARNESS_STDIN_TIMEOUT_S`, по умолчанию 10 с); в `CommandArgs` — флаги `stale`, `days`, `forget`.
```
