# Роли и протокол harness

Дата: 2026-10-28. Документ проектирования: в `prompts/index.yml` не
попадает. Проверяемые правила — в `expectations/roles.expect.ts`, здесь —
решения и их причины.

## Зачем

До ролей одна и та же работа жила в трёх формах: docs-keeper —
субагент и handoff-текст в docs-delta, судья — промпт plan-review и
задания `.judge/` для ручного субагента, обновление источника — строка
в source-sync. Роль сводит их в одно описание, которое работает и в
сессии агента, и в harness.

## Роль

Роль — файл `agents/<name>.md` источника (в проекте —
`.agents/agents/<name>.md`), отдельной сущности `roles/` нет: ключи
субагентов уже используют проекты.

- Frontmatter: `name`, `description`, `output` и необязательные
  `skills`, `tools`, `model`. Схема —
  `expectations/schemas/agent-frontmatter.schema.json`.
- `output` — сообщение протокола, которым роль возвращает итог.
  Без `output` файл — просто субагент, harness его не запускает.
- `model` — `opus` (по умолчанию), `sonnet`, `haiku`; адаптер переносит
  его в `.claude/agents/`.
- Тело — инструкции, нейтральные к инструменту. Ветка «есть инструмент
  `submit_result` — ответ им, иначе — текстом» делает одну роль
  пригодной для обоих режимов.

Режимы одной роли:

1. **Субагент в сессии агента** — адаптеры генерируют
   `.claude/agents/<name>.md` и `.codex/agents/<name>.toml`, основная
   сессия передаёт вход текстом. Работает в любом агенте.
2. **Исполнитель в harness** — `harness role run <name>` или действие
   состояния автомата (`roleOrHandoff`). Только Claude: так решено —
   описание ролей нейтрально, а `ModelRunner` оставляет дорогу runner'у
   под другой агент.

Роли сейчас: `docs-keeper` (`result`), `judge` (`verdict`, только
чтение). В контракт v3 судья не входит: его ставит будущий модуль
`expectations` для проектов-потребителей.

## Протокол

Сообщения — JSON Schema 2020-12, лишние поля запрещены, константа
`PROTOCOL` пакета:

- `result` — итог работы: `status` (`done` / `failed`), `changed`,
  `failed`, `questions`, `report`;
- `verdict` — ответ судьи: `answers` пакета вопросов или
  `contradictions` и `unmeasurable` проверки заголовков;
- `question` — блокирующий вопрос по формату skill `workflow`:
  `question`, `options` (от двух), `default`, `reason`.

Канал для `question` (инструмент `ask_user`) не сделан: ни judge, ни
docs-keeper человека не спрашивают, вопросы docs-keeper уходят в
`result.questions`. Спайк показал, что механика есть (см. ниже).

## Runner: CLI плюс MCP-канал

Роль запускается через `claude -p` из Claude Code пользователя, а не
через Claude Agent SDK.

- **Почему не SDK.** Документация Agent SDK (2026-10-28,
  `@anthropic-ai/claude-agent-sdk@0.3.312`): вход — API-ключ или облачные
  провайдеры; сторонним продуктам на SDK запрещено предлагать вход
  claude.ai без согласования с Anthropic. `@shahimat/harness` —
  публичный пакет, поэтому SDK — только с API-ключом. Документация
  называет `claude -p --output-format json` штатным путём из
  программы; harness вызывает инструмент пользователя под его входом.
  Прямой формулировки об этом случае в документации нет — это
  прочтение, а не подтверждённый факт.
- **Канал.** `harness role channel <message> --out <файл>` — MCP-сервер
  stdio без зависимостей с одним инструментом `submit_result`. Ответ
  проверяет ajv по схеме сообщения: невалидный — `isError` с путём к
  полю, модель исправляет и вызывает снова; валидный пишется в файл.
  Ответ текстом harness не читает.
- **Флаги.** `--setting-sources ""`, `--disable-slash-commands`,
  `--strict-mcp-config`, `--mcp-config` с каналом,
  `--permission-mode dontAsk`, `--tools` — `tools` роли (по умолчанию
  `Read, Glob, Grep`), `--allowedTools` — они же и
  `mcp__harness__submit_result`, `--no-session-persistence`. Задание —
  на stdin.
- **Схема инструмента** объявляется без `oneOf` / `anyOf` / `allOf`
  верхнего уровня (их не принимает API инструментов); полную схему
  проверяет канал.

## Проверенные факты (спайк 2026-10-28, `claude` 2.1.312)

- `claude -p` с MCP-каналом работает под входом по подписке, без
  `ANTHROPIC_API_KEY`.
- `--setting-sources "" --strict-mcp-config`: `CLAUDE.md` пользователя
  в прогон не попадает.
- MCP-сервер на голом JSON-RPC по строкам: `server/discover` (ответ —
  ошибка «нет метода», клиент продолжает), `initialize`,
  `notifications/initialized`, `tools/list`, `tools/call`.
- Клиент не проверяет аргументы по `inputSchema`: значение вне `enum`
  доходит до сервера — проверка на стороне harness обязательна.
- Ответ `isError` возвращается модели, она исправляет и повторяет вызов.
- Вызов инструмента может ждать ответа долго: 190 с ожидания ответа
  человека прошли без таймаута.
- `--input-format stream-json --output-format stream-json`: несколько
  ходов в одном процессе с одним `session_id`; `control_request`
  `interrupt` прерывает ход.
- В режиме `dontAsk` MCP-инструмент без `--allowedTools` отклоняется;
  `--tools ""` ограничивает только встроенные инструменты.
- `--allowedTools` принимает несколько значений: позиционный промпт
  сразу после него съедается — поэтому задание идёт на stdin.

## Где используется

- `expect judge --run` — задания `.judge/` отвечает роль `judge`
  параллельно, затем `--apply`. Без `--run` — прежний путь через
  субагента.
- `docs-delta start --file <намерения>` — `apply` выполняет роль
  `docs-keeper`; без файла или при провале роли — пауза с заданием
  агенту. Роли сказано, что процесс уже идёт: сама она docs-delta не
  запускает. При возврате из `verify` роль запускается заново, причину
  провала она пока не получает.
- `plan-review` заморожен и на роли не переведён.

## Дальше
