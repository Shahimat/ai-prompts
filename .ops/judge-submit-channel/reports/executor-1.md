# judge-submit-channel — отчёт executor (цикл 1)

## Диагноз (evidence)

1. Живая проба `askRole('judge')` в worktree воспроизвела отказ; транскрипт:
   судья сам пишет «`submit_result` в каталоге инструментов отсутствует».
2. Причина: спавненная headless-сессия загружает плагин из npm
   (`@shahimat/oc3@0.1.0`, кэш opencode) — в опубликованной версии
   `submit_result` не регистрируется вовсе (проверено по dist кэша: 8
   tools, submit отсутствует). Инструмент появится после публикации oc3 —
   это релизный каскад тикета 2, версии в тикете 1 не трогались.
3. Второй дефект: ответ судьи текстом не разбирался. Судья возвращает
   конверт `{message, data}` и/или заполняет все ветки вердикта
   (`answers` + пустые `contradictions`/`unmeasurable`) — `oneOf` схемы
   VERDICT отвергает смесь, fallback падал: «не вернула итог».
4. Третий зазор: когда инструмент появится, плагин исполняется в общем
   сервере opencode, где `HARNESS_SUBMIT_OUT` от спавна не виден — итог
   уйдёт в `<root>/.ops/submit/<sessionID>.json`, а `runRole` читал
   только временный файл канала.

## Что сделано

- `packages/ai-core/src/lib/role.ts`: извлечение итога переставлено на
  `roleOutcomeOf(role, sources)` — каскад «файл канала → файл сессии
  `.ops/submit/<id>.json` → текст ответа»; в тексте принимаются прямая
  форма, конверт `{message === role.output, data}` и голый массив
  ответов батча; пустые ветки вердикта рядом с заполненной отбрасываются
  (relaxVerdict). Сообщение отказа называет причину по каждому источнику
  и путь транскрипта.
- `packages/ai-core/src/commands/expect/index.ts` (judgeRun): транскрипт
  каждого прогона роли пишется в `expectations/.judge/transcripts/*.jsonl`
  (по умолчанию; каталог переопределяется env `HARNESS_EXPECT_TRANSCRIPT`),
  задание судье больше не требует файл и прямо разрешает текстовый JSON
  последним сообщением, строка отказа несёт причину и путь транскрипта.
- Тесты: `role.test.ts` — конверт, чужой message, голый массив, пустые
  ветки, файл сессии сервера, битый файл сессии + спасение текстом,
  причина и транскрипт в ошибке; `expect-cli.test.ts` — сквозной
  `judge --run` с конвертом в тексте (apply сам, report зелёный) и
  отказ роли (транскрипт записан, ошибка называет файл).
- Живая проверка реальной моделью: проба `askRole('judge')` после фикса
  возвращает итог (ранее — отказ). Сборка, typecheck, линт, тесты всех
  пакетов — зелёные; `npm run ci` доходит до бюджета ожиданий, где 4
  `?` (judged-warn без вердиктов) — их закрывает прогон судьи.
